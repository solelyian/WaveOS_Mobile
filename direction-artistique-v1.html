01

Principes

DA + UX

Le nom fait déjà le travail : onde, mouvement, rythme. Mais on a tranché dès la première réunion — WaveOS ne dessine pas l'eau, il se comporte comme elle. Aucune vague, aucune goutte, aucun bleu « océan » décoratif dans l'interface. L'eau vit dans le mouvement, la matière et le son — pas dans les motifs.

P1

La matière liquide, pas le décor marin

Verre, lumière, profondeur. Si un élément ressemble à une affiche de parc aquatique, il sort.

P2

Le geste mène, la matière suit

Réponse au toucher sous 16 ms. Chaque animation hérite la vélocité du geste et reste interruptible à tout instant.

P3

Chaque élément mérite sa place

Un écran = une hiérarchie lisible d'un coup d'œil. Le bruit visuel est traité comme un bug, pas comme un goût.

P4

La profondeur sert la hiérarchie

Le flou code la distance — fond, contenu, contrôle, alerte. Jamais d'effet qui ne dit rien.

02

Écran signature — Rubans & verre

DA + UI + Graphique

Le fond d'écran système, « Rubans » : base indigo profond (#0B0F22), traversée par quatre rubans de lumière inclinés — cyan, violet, magenta, orange. C'est le seul endroit du système où ces quatre couleurs apparaissent ensemble. Tout ce qui flotte au-dessus est en verre.

Météo
21°
Paris — dégagé

Pourquoi ça marche : les rubans donnent la profondeur (le verre a besoin de matière derrière lui pour exister), l'inclinaison à −16° donne le rythme, et l'ensemble reste assez sombre pour que le verre clair et le texte gardent leur contraste. Graphique : le fond est pré-calculé dans le compositor — le blur des rubans ne coûte rien au frame budget.

QA — règle de contraste

Le verre n'est pas une excuse pour un texte illisible. Texte jamais posé directement sur le wallpaper ; plancher de tint : blanc ≥ 38 % en mode sombre, encre ≥ 28 % en mode clair ; scrim adaptatif mesuré sur le fond réel (moyenne locale de luminance). Cible : 4,5:1 minimum, 7:1 sur le texte courant. Chaque écran est vérifié sur le pire cas — ruban magenta sous verre clair.

05

Géométrie

UI + DA

Trois formes, trois familles sémantiques. Squircle (superellipse n = 4,6) pour tout ce qui est une chose — icônes, tuiles, vignettes. Pill à coins continus pour tout ce qui est un contenant — panneaux, cartes, sheets. Capsule (r = h/2) pour tout ce qui est un contrôle d'action — boutons, barres de geste, sliders.

Débat tranché — DA vs UI

Le DA voulait tout en squircle « pour la signature ». UI a bloqué : sur un panneau large, la superellipse se lit comme un rectangle un peu bizarre, et son rayon variable complique les layouts internes. Tranché : squircle = choses (icônes, tuiles — là où la silhouette est vue entière) ; pill continu = conteneurs ; capsule = contrôles. La signature tient au motif « O », pas aux coins.

06

Matières — le verre WaveOS

UI + Graphique C/C++

Le verre est notre signature matière — inspiré de Liquid Glass, reconstruit autrement. Quatre couches, un seul shader : flou d'arrière-plan (dual-Kawase, 2 passes), tint par niveau, spéculaire en liseré supérieur, rim 0,5 pt. La réfraction lenticulaire réelle d'iOS 26 n'est rendue que sur la surface héro — voir débat en §09.

07

Mouvement — signature « Sillage »

Motion + Graphique

Ce qui rend WaveOS reconnaissable en mouvement : la matière se souvient du geste. Un élément déplacé se tend dans le sens du déplacement (stretch vélocité-lié), laisse un sillage de tension qui se résorbe, et atterrit en ressort légèrement sous-amorti héritant la vitesse du doigt — jamais de rebond artificiel à la fermeture.

snappy — k170 d18 (gestes directs) soft — k120 d14 (sheets, morphs) bounce — k140 d8 (retours ludiques) critique — référence

Réponse x(t) simulée en intégration semi-implicite, dt = 1/240 — le même solveur C que le prototype. L'overshoot de « bounce » est volontairement court : un rebond, pas deux.

09

Débats d'équipe, tranchés

Compte rendu DA

Réfraction temps réel — Motion vs Graphique

Motion : « Je veux la déformation lenticulaire partout, c'est ce qui vend le verre. »

Graphique : « Une réfraction par pixel sur chaque panneau, c'est le GPU saturé. Adieu 120 fps. »

Tranché : réfraction réelle uniquement sur la surface héro (le « O », la tuile d'app en morph). Tout le reste = dual-Kawase + spéculaire + rim — indiscernable en mouvement, coût constant et borné. Mesure : budget GPU ≤ 6 ms/frame sur cible médiane.

Chrome minimal vs affordance — DA vs UX

UX : « Sans poignée ni repère, personne ne devine le centre de contrôle. »

DA : « Une poignée permanente, c'est du chrome. Ça tue le minimalisme. »

Tranché : affordance contextuelle. La barre de geste et les hints apparaissent aux premières sessions, au long-press et en approche de bord ; ils s'effacent en usage fluide. Le geste est enseigné, pas affiché.

Lisibilité du verre — QA vs UI

QA : « Texte 17 pt sur verre 18 % au-dessus du ruban magenta : 2,1:1. Échec AA, point final. »

UI : « Monter le tint à 60 % partout, c'est du plastique opaque. »

Tranché : planchers de tint par niveau + scrim adaptatif calculé sur la luminance locale réelle du fond. On ne monte jamais le tint « au cas où » : le système mesure, puis décide.
